## Зачем это нужно

Бот генерирует задания «на основе ФГОС». Чтобы это было правдой, а не словами, генератору нужны:
- **каталог планируемых результатов**: дословные формулировки из официальных программ, с документом, разделом и **номером страницы PDF**;
- **поиск по тексту программ**, чтобы проверить, что тема учителя есть в программе класса;
- **текст страницы по номеру**, чтобы код проверил, что цитата действительно там есть.

Если в каталоге будет ошибка (не та страница, выдуманный текст), вся система потеряет доверие. **Точность важнее охвата.**

## G2. Загрузчик `downloader.py` · 🔴

```python
async def download_all(settings, progress=None) -> UpdateReport
```

- Для каждого источника из `sources.yaml`:
  - скачать через `httpx.AsyncClient`: таймаут 60 с, 3 попытки с паузой, `follow_redirects=True`, заголовок `User-Agent: SocratBot/0.1 (education prototype)`;
  - сохранить в `data/knowledge/raw/<source_id>.pdf`;
  - посчитать sha256;
  - записать в `data/knowledge/manifest.json` (source_id, url, sha256, bytes, checked_on, pages).
- Если sha256 не изменился — документ в `unchanged`, переиндексация не нужна.
- Ошибка одного документа не валит весь процесс: он попадает в `failed[source_id] = "причина"`.
- **CLI:** `python -m socrat.knowledge download` и `python -m socrat.knowledge status`.

## G3. Парсер PDF `parser.py` · 🔴

- PyMuPDF (`fitz`): страница за страницей, `page.get_text("text")`.
- **Номер страницы = индекс в PDF + 1** (1-based, «по нумерации PDF», как в кейсе). Печатный номер на странице не используем.
- **Чистка:**
  - склей переносы `слово-\nпродолжение` → `словопродолжение`;
  - убери повторяющиеся колонтитулы: строки, которые встречаются на >50% страниц;
  - нормализуй пробелы;
  - замени `­` (мягкий перенос) на пустую строку.
- **Результат:** `data/knowledge/pages/<source_id>.jsonl` — строки `{"source_id", "page", "text"}`.
- **Функция:** `get_page_text(source_id, page) -> str | None` читает этот файл; держи LRU-кэш.

## G4. Разметка разделов и нарезка `chunker.py` · 🟡

- **Разделы.** Определи заголовки регулярками (регистр игнорируй):
  - `ПЛАНИРУЕМЫЕ (ОБРАЗОВАТЕЛЬНЫЕ )?РЕЗУЛЬТАТЫ`;
  - `ЛИЧНОСТНЫЕ РЕЗУЛЬТАТЫ`, `МЕТАПРЕДМЕТНЫЕ РЕЗУЛЬТАТЫ`;
  - `Познавательные универсальные учебные действия`, `Коммуникативные …`, `Регулятивные …`;
  - `ПРЕДМЕТНЫЕ РЕЗУЛЬТАТЫ`;
  - `СОДЕРЖАНИЕ (УЧЕБНОГО ПРЕДМЕТА|ОБУЧЕНИЯ)`;
  - `(\d+|ПЕРВЫЙ|ВТОРОЙ|ТРЕТИЙ|ЧЕТВЁРТЫЙ…) КЛАСС`;
  - `К концу обучения в (\w+) классе`.
- **Каждому фрагменту:**
  - `section`: путь раздела, например «Планируемые результаты > Предметные результаты > 3 класс»;
  - `kind`: `ChunkKind`;
  - `grade`: если раздел классовый;
  - `subject_id`: для ФРП.
- **Нарезка:** 600–1200 символов по абзацам, не разрывая пункт списка. Фрагмент не пересекает раздел. Если переходит на следующую страницу — укажи `page_end`.
- `chunk_id = f"{source_id}:{page}:{n}"`.

## G5. Каталог планируемых результатов `catalog.py` · 🔴 самое важное

**Что выдаёт:** `data/knowledge/catalog/<level>_<subject_id>.json` и `data/knowledge/catalog/<level>_meta.json` — списки `Outcome` (контракт) в JSON. **Каталог коммитим в git.**

1. **Предметные результаты.** В каждой ФРП найди блоки «К концу обучения в N классе обучающийся научится:» (или похожие). Каждый пункт списка (`•`, `–`, `—`, `1)`) — отдельный `Outcome`:
   - `type = SUBJECT`, `grade = N`, `subject_id`;
   - `text` — **дословно** (после чистки G3);
   - `quote_is_verbatim = True`;
   - `section = "Предметные результаты > N класс"`;
   - `page` — страница, где **начинается** пункт;
   - `source_url = url + "#page=" + page`.
2. **Метапредметные результаты** (познавательные, коммуникативные, регулятивные) и **личностные** — из ФРП, разделы «Метапредметные результаты» и «Личностные результаты». Они относятся к уровню (НОО/ООО/СОО), а не к классу: `grade = None`, `subject_id` = предмет ФРП.
   - типы: `COGNITIVE` / `COMMUNICATIVE` / `REGULATORY` / `PERSONAL` — по подзаголовку;
   - если регулятивные разбиты на «самоорганизация» и «самоконтроль», оба идут в `REGULATORY`.
3. **ID:**
   - предметные: `f"{subject_id}-{grade}-P-{nn:02d}"`;
   - мета: `f"{subject_id}-{level}-{C|K|R|L}-{nn:02d}"`, например `math-noo-R-03`;
   - `nn` — порядковый номер в блоке.
   - ID **стабильны** между перезапусками: одинаковый PDF даёт одинаковые ID.
4. **Кейс SK01:** в `<noo>_math.json` **обязательно** добавь 6 записей из `data/reference/sk01/outcomes_reference.json`:
   - ID `P01`, `P02`, `C01`, `R01`, `K01`, `L01`;
   - `text = paraphrase`, `quote_is_verbatim = False`;
   - `grade = 3`, `section`, `page` — как в файле;
   - `source_id = FRP-MATH-2025`.

   **Кейс проверяет именно эти ID.**
5. **Самопроверка каталога** (`scripts/knowledge_report.py`):
   - таблица «предмет × класс → число предметных результатов»;
   - для 10 случайных записей: `text` найден в `get_page_text(source_id, page)`. Сравнивай после нормализации пробелов и регистра; допускается ≥ 0.9 по `difflib.SequenceMatcher`;
   - **Целевой показатель:** ≥ 95% записей проходят проверку цитаты. Отчёт — `reports/knowledge_report.md`.
   - Для `math`, 3 класс: результаты на стр. ~23 ФРП-MATH-2025 (кейс ссылается на стр. 23 и 18–20). Сверь глазами.

## G6. Индекс и поиск `index.py`, `retriever.py` · 🟡

- **BM25** (`rank_bm25.BM25Okapi`) по фрагментам.
  - Токенизация: нижний регистр, `re.findall(r"[а-яёa-z0-9]+")`, отбросить стоп-слова (короткий список).
  - Упрощённый стемминг: отрезать окончание до 4–5 символов основы, этого достаточно.
- **Эмбеддинги**, если заданы `EMBEDDINGS_BASE_URL` и `EMBEDDINGS_MODEL`:
  - `openai.AsyncOpenAI(base_url=..., api_key=...)`, `embeddings.create(model=..., input=[...])` батчами по 64;
  - хранить `data/knowledge/index/embeddings.npy` + `chunk_ids.json`;
  - при запросе — косинусная близость в numpy.
  - Если эмбеддинги не настроены или ошибка API — работаем только на BM25. Пиши WARNING в лог, но не падай.
- **Слияние:** Reciprocal Rank Fusion (k=60).
- **Фильтры:** `grade`, `subject_id`, `kinds`. Сначала фильтр, потом ранжирование. Если после фильтра пусто — ослабь фильтр по классу (±1).
- Индекс сохраняется на диск и грузится при старте за секунды. Пересборка — только в `update()`.

## G7. Класс `LocalKnowledgeBase` · 🔴

`src/socrat/knowledge/__init__.py` должен экспортировать:

```python
class LocalKnowledgeBase:  # реализует socrat.contracts.KnowledgeBase
    def __init__(self, settings: Settings): ...
```

- При создании загружает manifest, каталог, индекс. Если чего-то нет — `status().ready = False` и описание в `problems`, без исключений.
- `list_subjects(grade)` — см. G1.
- `check_topic(grade, subject_id, topic)`:
  - поиск по `kinds=[CONTENT, SUBJECT_RESULT]` с фильтром класса и предмета, k = 5;
  - `in_program = True`, если лучший нормированный score ≥ порога (подбери порог на 10 темах: 5 заведомо из программы, 5 заведомо нет — «квадратные уравнения» для 3 класса, «фотосинтез» для математики);
  - `suggestions` — до 5 коротких названий тем из заголовков или первых строк найденных фрагментов раздела «Содержание обучения» этого класса.
- `get_outcomes(grade, subject_id, types, query, k)`:
  - предметные результаты этого класса и предмета + мета и личностные результаты уровня (из ФРП этого предмета);
  - если `query` задан — сортировать по BM25-близости к `query`;
  - для math/3 **всегда** включать P01…L01.
- `get_outcome(id)`, `get_source(id)`, `get_page_text(id, page)`, `search(...)`, `status()`.
- `async update(progress)` — G2 → G3 → G4 → G5 → G6 для изменённых документов, с сообщениями в `progress`, например «Скачиваю ФРП Математика 1–4 (3/25)…». Возвращает `UpdateReport`.
- `async ingest_school_material(filename, content, progress)`:
  - PDF — через G3; DOCX — python-docx, «страница» = блок по 3000 символов;
  - `doc_type = SCHOOL_MATERIAL`, `is_normative = False`, `source_id = "SCHOOL-" + sha256[:8]`;
  - в каталог **не** добавлять, только в поиск.

**CLI** (`python -m socrat.knowledge ...`): `download`, `build` (parse + chunk + catalog + index), `status`, `search "<запрос>" --grade 3 --subject math`, `outcomes --grade 3 --subject math`, `check-topic --grade 3 --subject math "внетабличное умножение"`.
