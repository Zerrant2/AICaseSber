# Сократ — помощник педагога для диагностических работ

**Кейс SK01 · команда T004 Fazbear Entertainment, Inc.**: Калюжный А. О., Редняков Д. А., Звонарёв И. С.

«Сократ» — Telegram-бот для педагога. Он помогает составить диагностическую работу на 15–20 минут, выдаёт лист ученика и методичку в `.docx`, показывает связь заданий с выбранными планируемыми результатами из каталога источников. Второй сценарий разбирает типичную ошибку, описанную педагогом без имён детей, и предлагает проверочные вопросы и приёмы для следующего урока.

> **Подробно о продукте** — сценарии, как устроены генерация и проверки, чем отличаются роли, что реализовано и что планируется: [docs/OVERVIEW.md](docs/OVERVIEW.md).

## Что уже работает

- Вход по паролю администратора или педагога, сессии с ограниченным сроком и блокировка перебора паролей.
- Создание работы: класс, предмет, тема, варианты, фокус УУД и число заданий; проверка запроса и показ предупреждений до генерации.
- Два Word-файла: ученический лист без ответов и методичка с решениями, картой результатов, временем, наблюдаемыми признаками и источниками.
- Анализ типичной ошибки с выдачей результата в чате и отдельного Word-файла.
- Отзывы по заданиям, перегенерация, разбор обезличенного ответа и ответа на вопрос рефлексии.
- Админ-панель: педагоги, статус и обновление нормативной базы, загрузка материалов школы, расходы.

Режим `USE_FAKES=true` использует демонстрационные данные кейса SK01 и не обращается к LLM. Он удобен для первого запуска. При `USE_FAKES=false` бот использует реальное ядро генерации и локальную нормативную базу; для генерации нужен ключ LLM.

## Первый сценарий для проверки

В боте нажмите «📝 Создать работу» и выберите **математика, 3 класс, умножение и деление, все три уровня, 4 задания**. Дождитесь двух `.docx`. Затем попробуйте «👍/👎 по заданиям» и «🔍 Анализ типичной ошибки». На ученическом листе уровни подписаны нейтрально: «Вариант А / Б / В».

## Нормативная база

В репозитории есть каталоги планируемых результатов и извлечённые тексты страниц ФРП для 1–9 классов. Для 1–4 классов доступны математика, русский язык, литературное чтение и окружающий мир; для 5–9 классов — предметы, перечисленные в [отчёте по базе](reports/knowledge_report.md). Каталог содержит источник, раздел и страницу каждого результата. PDF-оригиналы в репозитории не хранятся.

После чистого клонирования каталог и страницы уже доступны. Поисковый индекс может быть построен при запуске. Для обновления источников выполните:

```powershell
python -m socrat.knowledge download
python -m socrat.knowledge build
python -m socrat.knowledge status
```

Первые две команды скачивают PDF и пересобирают каталог с индексом. Статус базы и обновление также доступны в админ-панели бота. Подробности источников и проверки страниц приведены в [отчёте](reports/knowledge_report.md).

## Установка из ветки `release`

Чтобы получить готовую версию, клонируйте сразу ветку `release`:

```powershell
git clone --branch release --single-branch https://github.com/Zerrant2/AICaseSber.git
cd AICaseSber
```

Если репозиторий уже клонирован, обновите ветку командами `git fetch origin`, `git switch release`, `git pull --ff-only origin release`. Затем выполните шаги ниже: заполните `.env` и выберите локальный запуск или Docker Compose.

Сообщение GitHub «Compare & pull request» после обновления `release` предлагает создать PR в `main`. Для установки оно не нужно: `release` опубликована как отдельная ветка и не сливается целиком с `main`.

## Подготовка

1. Создайте бота через [@BotFather](https://core.telegram.org/bots/tutorial): отправьте `/newbot`, следуйте подсказкам и сохраните выданный токен.
2. Скопируйте `.env.example` в `.env`. Заполните `TELEGRAM_BOT_TOKEN`, `ADMIN_PASSWORD` (не менее 8 символов) и `APP_SECRET` (не менее 32 символов). Секрет можно создать командой `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Файл `.env` не коммитится.
3. Для демонстрации установите `USE_FAKES=true`. В этом режиме LLM не вызывается; `LLM_PRICE_IN_PER_1M` и `LLM_PRICE_OUT_PER_1M` можно оставить пустыми.
4. Для реальной LLM создайте ключ на [странице ключей OpenRouter](https://openrouter.ai/settings/keys), укажите его в `LLM_API_KEY`, задайте `LLM_MODEL=deepseek/deepseek-v4.1-flash`, `LLM_JSON_MODE=prompt`, `LLM_MAX_TOKENS=12000` и установите `USE_FAKES=false`. Инструкции OpenRouter по [подключению API](https://openrouter.ai/docs/quickstart). Никому не отправляйте токен бота или ключ API.

### Локальный запуск

Требуется Python 3.11 или новее; в CI используется Python 3.12.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
# Заполните .env по шагам выше.
python -m socrat.bot
```

Для Linux/macOS вместо активации PowerShell используйте `source .venv/bin/activate`, а вместо `Copy-Item` — `cp`. База SQLite создаётся при старте в `data/socrat.db`. Для входа отправьте боту `/start`, затем пароль администратора из `.env`. Педагогам пароли выдаёт администратор через админ-панель.

### Docker Compose

```bash
cp .env.example .env
# Заполните .env, включая USE_FAKES=true для демонстрации.
docker compose up --build -d
docker compose logs -f bot
```

Контейнер запускает `python -m socrat.bot`; каталог `./data` подключён как том для SQLite и материалов базы. Один и тот же токен Telegram-бота не следует использовать одновременно для локального процесса и контейнера с long polling. В `docker-compose.yml` приведён закомментированный пример сервиса Ollama для локальной модели.

Проверить базу внутри контейнера можно без запуска второго экземпляра бота:

```bash
docker compose build bot
docker compose run --rm --no-deps -e USE_FAKES=false --entrypoint python bot -m socrat.knowledge status
```

При запуске из корня репозитория каталог и извлечённые страницы доступны через том `./data:/app/data`; статус должен показывать `Ready: True`. SQLite в том же каталоге сохраняется между перезапусками контейнера.

## Стоимость и ограничения

Для `deepseek/deepseek-v4.1-flash` на [странице OpenRouter](https://openrouter.ai/deepseek/deepseek-v4.1-flash) на 24.09.2026 указано **$0.04 за 1 млн входных** и **$1.00 за 1 млн выходных токенов**. Одна работа из трёх уровней на замере 24.09 стоила **$0.0365** (6 вызовов, 126 с); ориентир — **$0.025–0.045**; расчёт и допущения приведены в [документе о стоимости](docs/cost.md). Укажите текущие тарифы в `LLM_PRICE_IN_PER_1M` и `LLM_PRICE_OUT_PER_1M`, если нужен расчёт в приложении. Цена зависит от провайдера и может измениться; сверяйте страницу модели перед запуском. Расходы по выполненным работам показывает админ-панель. Режим фейков не делает платных LLM-вызовов.

Система не заявляет полного покрытия ФГОС. Она показывает только результаты, присутствующие в каталоге, с источником, разделом и страницей; внутренние коды результатов не являются номерами пунктов ФГОС. Загруженные материалы школы используются как контекст и не считаются нормативными источниками. Время работы расчётное. Не вводите имена и другие данные детей; описание ошибки и ответ должны быть обезличены. Разбор ответа фиксирует наблюдаемые признаки, не ставит диагноз и не оценивает личность.

Архитектура и границы компонентов описаны в [ARCHITECTURE.md](ARCHITECTURE.md), принятые решения — в [журнале решений](docs/decisions.md).
