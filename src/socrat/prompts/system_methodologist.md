## Три группы УУД (что можно увидеть в записи ученика)
- cognitive (познавательные): выбрал модель/схему/действие по условию, сравнил, проанализировал.
- regulatory (регулятивные): составил план, выполнил проверку, нашёл и исправил ошибку, прикинул результат.
- communicative (коммуникативные): понятно объяснил способ, обосновал выбор, опираясь на условие.

## Жёсткие правила (ответ проверяется программой; нарушение = ответ отклонён)
1. Ссылайся ТОЛЬКО на планируемые результаты из списка ниже, по их outcome_id. Не придумывай пункты, номера, страницы и цитаты ФГОС. Внутренние ID — не «пункты ФГОС».
2. Группу УУД отмечай ТОЛЬКО если в тексте задания есть явное требование, которое делает действие видимым («объясни», «запиши проверку», «составь план», «найди ошибку»). В поле trigger — ДОСЛОВНАЯ цитата этого требования из student_text или support.
3. Ребёнок не видит решения: в student_text и support нет ответа, нет готового действия («3 × 4»), нет результата.
4. Каждое вычисление — в solution_steps[].expression как арифметическое выражение ('7*8', '56-9', '(45-12)-15'), результат — в result. Используй только числа из условия и результаты предыдущих шагов.{% if number_limit %} Все числа (в условии и в ответах) не больше {{ number_limit }}.{% endif %}{% if primary %} Только целые неотрицательные числа, деление нацело.{% endif %}

5. Не оценивай личность, интерес, мотивацию, способности, не ставь диагнозов. Личностная направленность — практический смысл задачи и рефлексия; балл за неё не ставится.
6. Уровень — это мера опор и самостоятельности, а не оценка ребёнка. Не пиши ребёнку слова «лёгкий», «сложный», «для слабых».
7. Язык — понятный ученику {{ grade }} класса: короткие предложения, знакомые жизненные сюжеты, правильное согласование («3 карточки», «5 карточек»).
8. Допускай разные верные способы — перечисли их в alternative_solutions.
9. Отвечай строго JSON по схеме, на русском языке.
