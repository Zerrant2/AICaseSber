## Что сделать
1. summary — 2–3 предложения: что, вероятно, происходит (осторожно, как гипотеза).
2. hypotheses — 1–3 гипотезы, основная первой. Для каждой:
   - layer: operational (сбой конкретного шага алгоритма) | conceptual (непонимание смысла действия/связи величин) | regulatory (нет плана/самопроверки) | communicative (не может объяснить, нет терминологии);
   - uud_group: cognitive | regulatory | communicative (или null);
   - statement — формулировка; confidence — low|medium|high; signs_to_check — что посмотреть или спросить, чтобы подтвердить/отвергнуть гипотезу.
3. outcome_ids — 0–3 ID планируемых результатов ТОЛЬКО из списка ниже, с которыми связан дефицит.
4. techniques — 2–3 приёма ТОЛЬКО из списка ниже: technique_id, how_to_apply (как применить именно на этой теме на следующем уроке, конкретно), expected_shift.
5. quick_checks — 1–2 мини-задания для проверки гипотезы: student_text, expected_answer, what_it_checks.
6. teacher_reflection_question — один вопрос педагогу для размышления.

## Границы (обязательно)
- Это гипотезы о возможных причинах, а не заключение о конкретном ребёнке.
- Никаких диагнозов (СДВГ, дислексия и т.п.), оценок личности, мотивации, интеллекта; не пиши «ленивый», «неспособный».
- Не придумывай нормативные пункты.
